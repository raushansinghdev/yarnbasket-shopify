# Audit: everything built so far (2026-10-02)

Raushan asked for a full review before pushing: find the issues, mistakes and bugs in the header and navigation, the home page, the cart, search and the search results page, and fix them.

## How it was checked

- **`npm run check`** (full run): Chrome, Safari (WebKit) and Firefox, on phone and desktop. It covers speed, smoothness, motion, accessibility, the search panel, the results page and the cart. **57/57 pass.**
- **`npm run audit`** (new, `tools/audit.mjs`) crawls 19 page types on phone and desktop in each of the three browsers. Pages: home, collections, all products, all 11 products, cart (empty and with items), search (empty, results, none), contact, blog, login, privacy policy, 404. It looks for:
  - script errors, and failed requests to our own pages
  - Liquid errors and missing translations
  - duplicate ids and ARIA or label references to ids that don't exist
  - images without alt, and the number of h1s per page
  - sideways scroll
  - axe (WCAG 2.2 AA + best practice)

  **Clean in all three browsers after the fixes.**
- **Cart and results-page flows in Safari (iPhone) and Firefox:**
  - cart: add → pop-up → View cart → + / − / bin / Undo → Esc → header cart → Back → cart page stepper
  - results page: the lens jumps to the box, and sort works in place

  All pass.
- **Edge cases:**
  - 3 fast taps send one request
  - typing 99 on an item with 3 in stock gives 3, with the reason shown
  - the gift note survives a reload
  - pressing Checkout while a removal is saving
  - the product page adds the option you chose
  - a sold-out product's button is disabled
  - two quick sorts: the last one wins
  - the drawer on a landscape phone
  - Tab stays inside the open drawer
- **`shopify theme check`:** clean (74 files).

## Found and fixed

| # | Where | Problem | Fix |
|---|-------|---------|-----|
| 1 | Cart | **Pressing Checkout while a change was still saving did nothing.** The save redraws the cart, the Checkout button that was pressed is replaced, and the browser refuses to submit with a button that's no longer on the page. Found by the "remove, then Checkout at once" test | cart.js waits for the save, then submits the current form with its current Checkout button. The same applies to the path that goes through the drawer's history step |
| 2 | Cart drawer | **The page behind could scroll** while the drawer was open (the drawer lacked the scroll lock the menu drawer has). On phones, swiping past the end of the list moved the page | Added `data-scroll-lock` to the drawer |
| 3 | Every page | **Duplicate id `yb-mark-ball-drawer`:** the empty cart's logo and the menu's logo used the same id | The empty cart's logo now uses `cart-empty-drawer` / `cart-empty-page` |
| 4 | `/collections/all` (and every collection) | **Phones scrolled sideways in Safari and Firefox.** The collection page was still Skeleton's starter, with 500px-wide grid columns, and "Shop all" links already lead there | **Interim collection page** until build-plan Phase 3: the title, the compact cards 2/3/4/5 across, page links, and an empty state. It has a hidden "Products" h2 so the heading order is correct |
| 5 | Search results | **A late reply could undo a newer sort.** With two quick changes, the first request could arrive last and show the older order. A failed old request would also reload the page | search-page.js keeps only the newest reply and ignores failures of older ones |
| 6 | Search results | The header lens and the menu's Search row were announced as "opens a pop-up" on /search, where they jump to the page's box (found by the search session) | Those attributes are dropped on /search (b49492e) |
| 7 | Repo | A stray screenshot file called `--eval` in the repo root, written by a screenshot command missing its output argument | Deleted. `tools/cdp.mjs` now refuses to run without a proper output argument |

## Looked at, and not bugs

- **Shopify's own messages on a local server:**
  - shop.app framing
  - `_shopify_test` cookie warnings in Firefox
  - `sf_private_access_tokens` 400s
  - cross-origin script warnings in WebKit
  - the new customer accounts redirect from /account/login

  None of these come from the theme, and they don't appear on the real domain. `npm run audit` filters them out.
- **"View transition aborted"** appeared once in a test that stubbed the checkout page. It's an artifact of the stub; real checkout is on Shopify's domain.
- **One Tab stop "outside" the open cart drawer** is the browser's address bar. Chrome lets Tab reach its own toolbar from a modal, which is expected.
- **A cold-start LCP of 2,372ms** in one quick run. The full run passes, and repeated runs measure about 800ms with or without cart.js.
